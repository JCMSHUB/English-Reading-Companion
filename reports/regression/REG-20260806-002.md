# REG-20260806-002 · 伴读本地交付回归

## 被测版本

- `english-reading-companion` 1.0.1
- 测试日期：2026-08-06

## 变更目标

将完整文章伴读从“可选择保存的聊天输出”改为必需的本地交付物，避免分析完成后没有 `content/readings/` 文件。

## 测试样本

- 单篇完整伴读：检查保存目标、来源文件、命名信息、草稿状态和交付路径规则。
- 既有版本契约：检查 `VERSION`、`SKILL.md` 与 `agents/openai.yaml` 的版本一致性。

## 结果

| 检查项 | 结果 | 证据 |
|---|---|---|
| 本地保存为强制步骤 | 通过 | `SKILL.md` 要求完整文章伴读在最终交付前写入 `content/readings/NNN-english-slug.md`。 |
| 不得只留在聊天 | 通过 | `SKILL.md` 明确禁止只在聊天中交付。 |
| 命名与来源门槛 | 通过 | 编号、slug、标题或来源不完整时必须停止询问。 |
| 覆盖保护与初始状态 | 通过 | 新文件使用 `draft`，已有文件须经明确确认才可覆盖。 |
| 版本一致性与自动测试 | 通过 | `python3 -m unittest discover -s tests/regression -v` 运行 4 项，全部通过。 |

## 与上一版本的差异

1.0.0 仅规定“保存时”的元数据，未把保存本身设为强制步骤。1.0.1 增加保存、验证和路径回执的完整交付契约。

## 发布建议

建议发布为补丁版本 1.0.1。

## 已知限制与后续候选

- 当前仓库没有符合命名规范的 Markdown 原文，因此本次只验证技能契约，未生成或覆盖任何内容资产。
