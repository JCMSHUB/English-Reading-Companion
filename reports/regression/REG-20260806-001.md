# REG-20260806-001 · 技能版本可见性回归

## 被测版本

- `english-reading-companion` 1.0.0
- `english-reading-ab-workflow` 1.0.0
- 测试日期：2026-08-06

## 变更目标

确保每次技能调用都向用户显示实际使用的版本，并让保存产物、技能正文和 UI 元数据使用一致版本。A/B 工作流必须同时显示自身版本和实际安装的伴读技能版本。

## 测试样本

- 单篇伴读调用：以 *The Best Life Stories* 中任一独立短篇作为代表场景，检查伴读输出头和 Markdown 元数据契约。
- A/B 调用：检查 Baseline、Skilled、Comparison 三产物的双版本记录契约。
- 既有方法回归：检查 Story、Language、Thinking、Beyond the Words 四层结构及已知重点表达参考仍然存在。

本次修改不改变伴读分析方法，因此未重新生成正式伴读内容。

## 与上一版本的差异

上一状态是未声明版本的导入基线。本次建立首个正式项目版本 `1.0.0`，新增：

- 每个技能的机器可读 `VERSION`；
- 调用时的用户可见版本行；
- 产物版本元数据约束；
- A/B 双技能版本核对；
- 自动回归测试和版本记录。

伴读方法、Baseline 隔离规则和 Comparison 评价标准未改变。

## 发布建议

建议将两个技能的 `1.0.0` 作为项目内首个正式版本提交。项目内结构和版本契约验证通过。

## 已知限制与后续候选

- 两个技能尚未安装到 Codex 全局技能目录，因此当前会话无法完成真实的自动发现调用测试。
- 安装更新后的技能并启动新会话后，应以一篇短故事执行一次端到端烟雾测试，确认界面和实际输出均显示 `1.0.0`。
- `quick_validate.py` 需要提供 `PyYAML` 的 Python 环境；当前使用 Ruby YAML 解析完成等效元数据检查。
